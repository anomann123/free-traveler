# Free Traveler — UI·UX Plan

**Document ID:** UIUX-TRAVEL-001
**기반 문서:** `00_PRD.md`, `02_SRS_BASELINE.md`, `PROJECT_SCOPE.md`, `03_UI_COVERAGE_ANALYSIS.md`, `design-reference/vendor/airbnb/DESIGN-airbnb.md`(참고용, 상표·색상 미사용)
**범위:** SCR-001~005 5개 디자인 Screen의 디자인 토큰, Header/Footer 공통 구조, Section 배치, 반응형 규칙, 상태(State) 정의

---

## 1. 디자인 원칙

1. Free Traveler는 흰 배경(Canvas) 위에 짙은 회색 텍스트, 코랄 포인트 하나만 사용하는 절제된 마켓플레이스 톤을 따른다. Airbnb 참고본에서는 여백 리듬·카드 밀도·1단계 그림자 체계 같은 **레이아웃 문법만** 차용하고, Rausch 색상·Cereal 폰트·워드마크 등 상표 요소는 사용하지 않는다.
2. 오류·경고·안전정보(외교부 여행경보, stale 배지)는 코랄과 혼동되지 않도록 별도 semantic color(빨강/주황/파랑/초록)를 사용한다.
3. 모든 화면은 Header–Section들–Footer 순서를 지키며, 각 Section은 제목·1~3문장 설명·실제 콘텐츠(또는 CTA)를 갖춘다. 데이터가 없을 때도 안내 문장과 다음 행동을 제공해 빈 화면처럼 보이지 않게 한다.
4. Desktop 1440px, Mobile 390px 두 기준을 모든 Section에 기록한다.
5. 키보드 포커스 링과 44×44px 이상 터치 영역을 모든 인터랙티브 요소에 적용한다.

### 2.4 접근성 공통 규칙

- 포커스 링: 모든 인터랙티브 요소에 `2px solid color.coral` 아웃라인 + 2px 오프셋(호버가 아닌 `:focus-visible` 기준).
- 터치 영역: 버튼·아이콘 버튼·Chip·Card 내 클릭 영역 최소 44×44px.
- 색상 단독 구분 금지: 여행경보 단계·모집 상태·stale 여부는 색상 배지 + 텍스트 라벨을 함께 표기한다.

## 4. SCR-001 `/` 메인

**사용자 목표:** 국내·해외 여행지를 발견하고, 여행 도구·동행·대표 소개로 자연스럽게 이동한다.
**Section 수:** 7 (Hero 1 + Card Grid 3 + Chip 1 + Card Grid/Empty 1 + 좌우 분할 CTA 1)

| # | Section | 유형 | Desktop(1440px) | Mobile(390px) | 이동/상호작용 |
|---|---|---|---|---|---|
| 1 | 여행지 검색 Hero | Hero | 화면 높이의 약 60%(다음 Section 시작이 보이도록 전체 높이 차지 금지), 배경 사진 위 검색창(목적지 키워드)과 "여행 도구 살펴보기" 코랄 버튼을 나란히 배치 | 검색창 풀폭, CTA 버튼 아래로 스택 | 검색창 제출 시 SCR-001 내 검색 결과로 스크롤, CTA는 `/travel-tools` 이동 |
| 2 | 국내 인기 여행지 | Card Grid(6) | 3열×2행, 카드 비율 4:3 사진+제목+테마 Chip 1개 | 1열 스택, 가로 스크롤 없이 세로 나열 | 카드 클릭 시 같은 화면에서 여행지 상세 Drawer 오픈(REQ-FUNC-001~006) |
| 3 | 해외 인기 여행지 | Card Grid(6) | 3열×2행, 국내 그리드와 배경 톤을 `surface-soft`로 구분해 반복감 완화 | 1열 스택 | 카드 클릭 시 상세 Drawer, Drawer 내 "국가 안전정보 보기" 링크 노출 |
| 4 | 여행 동기·테마 | Chip 목록(6) | 가로 1행 Chip 그룹("바다", "미식", "역사·문화", "액티비티", "휴양", "도심") + 설명 문장 | 2줄 Wrap Chip | Chip 선택 시 2·3번 Section 카드가 해당 테마로 필터링 |
| 5 | 국가별 주의사항 | Card Grid(6) | 3열×2행, 카드에 국가명+최종 확인일 배지(`color.safety-info` 또는 stale 시 `color.warning`) | 1열 스택 | 카드 클릭 시 같은 화면에서 안전정보 Drawer 오픈(REQ-FUNC-046~054) |
| 6 | 최근 동행 이야기 | Card Grid(3) / Empty | 데이터 있을 때: 최근 등록된 모집글 3개(국가·기간·모집 상태) / 데이터 없을 때: "아직 등록된 동행글이 없어요" 안내 + 이용 방법 3줄 + "동행 글 작성하기" CTA | 1열 스택, Empty 문구 동일 | 카드 클릭 시 `/mates` 이동, Empty CTA는 로그인 여부에 따라 `/mates/new` 또는 `/account` 로그인 탭 |
| 7 | free_traveler 소개 | 좌우 분할 + CTA Banner | 좌: 대표 사진, 우: 한 줄 소개 + "50+ Trips" "30+ Countries" 지표 카드 + "대표 이야기 더 보기" CTA | 사진 위, 텍스트·지표·CTA 아래로 스택 | CTA는 `/about` 이동(REQ-FUNC-057~063) |

**상태(State) 정의**

| 상태 | 적용 Section | 설명 |
|---|---|---|
| Loading | 2, 3, 5, 6 | 스켈레톤 카드(제목/이미지 영역만 회색 블록) |
| Success | 전체 | 위 표의 기본 레이아웃 |
| Empty | 4(필터 결과 없음), 6(모집글 없음) | 조건 완화 안내+초기화 버튼(4), 작성 CTA+이용 방법(6) |
| Error | 5(안전정보 Drawer 열람 실패), 1(검색 처리 실패) | "여행지 정보를 불러오지 못했습니다. 다시 시도해 주세요" + 재시도 버튼 |
| Unauthorized | 해당 없음 | 전 Section 비로그인 열람 가능(Public) |

**Alt 텍스트 예시:** "제주 성산일출봉 해안 절벽과 유채꽃밭", "태국 방콕 왓아룬 사원 야경" — 장소·구도를 설명하는 실제 문장만 사용한다.

## 6. SCR-003 `/travel-tools` 통합 여행 준비

**사용자 목표:** 항공·숙소 조건을 정리해 외부로 이동하거나 동행 모집글을 작성한다.
**Section 수:** 6, 3개 탭(항공편 / 숙소 / 동행 구하기)의 입력·검증·완료 상태를 서로 분리해 관리한다.

| # | Section | 유형 | Desktop(1440px) | Mobile(390px) | 이동/상호작용 |
|---|---|---|---|---|---|
| 1 | 이용 안내 Intro | 3단계 안내 | "① 조건 입력 → ② 요약 확인 → ③ 외부 사이트 이동" 3단계 아이콘 행 + 한 문장 설명 | 세로 스택 3단계 | 없음(안내) |

| 6 | 동행 구하기 | Form + Banner | 비로그인: 로그인 안내 카드("로그인하고 동행을 구해보세요" + 로그인 CTA) / 로그인: 모집글 작성 Form(제목·국가·지역·기간·인원·스타일·설명·안전수칙 동의) + 안전 안내 배너(`color.warning-bg`, "연락처는 본문에 남기지 마세요") | 동일 구조, Form 1열 | 작성 완료 시 SCR-004 해당 모집글 상세로 이동(REQ-FUNC-027~032, 080) |

**상태(State) 정의(탭별 독립)**

| 상태 | 적용 위치 | 설명 |
|---|---|---|
| Loading | 4(외부 이동 버튼 클릭 직후) | 버튼 스피너, 새 탭 오픈 대기 |
| Success | 3→4 전환, 6 작성 완료 | 요약 표시, 작성 완료 Toast("모집글이 등록되었습니다") |

## 8. SCR-005 `/account` 계정·관리

**사용자 목표:** 로그인·가입하고, 프로필과 내 활동(글·요청·차단)을 관리하며, 관리자는 신고·외부 URL을 처리한다.
**구조:** Header–탭 영역–Footer. 탭은 역할에 따라 조건부로 렌더링하며, 역할에 없는 탭은 DOM에 존재하지 않는다.

| 탭 | 노출 대상 | 구성 Section |
|---|---|---|
| A. 로그인/가입 | Guest | ① 계정 기능 Intro(로그인하면 가능한 것 요약) → ② 로그인·회원가입·비밀번호 재설정 Card 3개(Card Grid) → ③ 로그인 후 가능한 기능 3단계 안내(동행 글쓰기·참가 요청·즐겨찾기) → ④ 보안 안내 배너(비밀번호 정책, 개인정보 처리방침 링크) |
| B. 프로필 | Member, Admin | ① 프로필 요약 Card(닉네임·연령대·성별·여행 스타일·성인 확인 상태 배지) → ② 프로필 수정 Form |
| C. 내 활동 | Member, Admin | ① 내가 쓴 모집글 목록(상태 배지: 모집중/마감) + 새 동행글 작성 CTA → ② 내가 보낸/받은 참가 요청 목록(승인·거절 액션) → ③ 차단 목록(해제 액션) |
| D. 관리자 | Admin만 | ① 신고 목록 + 상태 필터(OPEN/REVIEWING/RESOLVED/DISMISSED, 목록형, 통계 카드 없음) → ② 항공·숙소 외부 URL 설정 Form(HTTPS 허용목록 검증) |

**Desktop(1440px):** 좌측 세로 탭 메뉴(폭 240px) + 우측 콘텐츠(최대 1000px). **Mobile(390px):** 상단 가로 스크롤 탭 바 + 콘텐츠 풀폭 스택.

**상태(State) 정의**

| 상태 | 적용 탭 | 설명 |
|---|---|---|
| Loading | B, C, D | 프로필/목록/신고 큐 스켈레톤 |
| Success | 전체 | 기본 레이아웃, 저장/처리 후 성공 Toast |
| Empty | C(내 글·요청·차단 없음), D(신고 없음) | "아직 작성한 동행글이 없어요" + 작성 CTA / "처리할 신고가 없어요" + 다음 확인 주기 안내 |
| Error | A(로그인/가입 실패), B(저장 실패), D(URL 저장 실패: 허용되지 않는 프로토콜) | 필드 인라인 오류 + 상단 오류 배너 |
| Unauthorized | D(비관리자 접근), C(비로그인 접근) | 탭 자체 미노출이 기본이며, 직접 URL 접근 시 "이 페이지를 볼 수 있는 권한이 없어요" 안내 + 로그인/홈 이동 CTA |

> Dashboard형 통계 카드나 그래프는 만들지 않는다. 관리자 탭은 목록과 필터, 단순 폼으로만 구성한다.

## 10. 빈 상태·오류 문구 원칙

- 금지 문구: `Lorem ipsum`, `준비 중`, `정보 확인 필요`, 내용 없는 빈 카드.
- 대체 원칙: (1) 무엇이 없는지 한국어 완성 문장으로 설명 → (2) 이용 방법 또는 이유 한 줄 → (3) 다음 행동 CTA. 예: "아직 등록된 동행글이 없어요. 원하는 국가와 기간으로 첫 모집글을 작성해 보세요." + "동행 글 작성하기" 버튼.
- 이미지 alt 텍스트는 실제 장소·구도를 설명하는 문장으로 작성하고 "이미지", "사진1" 같은 placeholder를 쓰지 않는다.
